# 方案 b：串联重复区间内不取锚点（--tr-dist）评估（2026-10-14）

前置：
- `docs/2026-10-14-w500-sp-diagnosis.md`：W=500 的 SP 下降来自锚点落在串联重复内部。
- `docs/2026-10-14-maxocc-filter-eval.md`：方案 a（`--max-occ`，跳过重复 minimizer）不够，因为重复区里的唯一锚点同样会把 indel 钉住。

**结论：方案 b 在 1Mbp 和 500kbp 上有效，原始 SP 超过默认参数；250kbp 在 1256 位点（大插入）退步，原因待查。**

## 算法
- 对每次比对的共识 t 和 query q 各做一次：同一个 minimizer 在 D bp 内再次出现时，记周期 p 为两次结束位置之差，标记区间 [首次出现起点 − p, 再次出现终点 + p]；相距不超过 50 bp 的区间合并（`tr_intervals`）。
- 实现上用哈希表记录每个 minimizer 上一次出现的位置，与 D 无关，是 O(n)。minipoa 只用正链 k-mer（`mm_sketch` 中 `z = 0`），所以不会把反向重复误判为串联重复。
- 锚点在 t 或 q 上只要与区间有重叠就不生成（`collect_anchors`，用前缀和判断）。判断放在链化之前，使 `chain_dp` 的选点和带宽标记都按合并后的段重新计算。`--max-occ` 的计数口径不变。
- 思路来源：minimap2 的 `is_tandem`（seed.c:47，相邻 minimizer 相同则标记；align.c:804，不把它当作 DP 断点）与 sdust 的区域掩盖（map.c:33）。这里把"相邻"放宽为"D bp 以内"，按区域掩盖，并对共识和 query 两侧都做。

## 1256 位点（250kbp 原始 SP 下降的来源）的根因（已核实）
- 位点注释与文献核对见 `docs/2026-10-14-is6110-1256-sites.md`：本区为 H37Rv dnaA–dnaN 基因间区（oriC），A 位点即已知的 Beijing A1 插入（H37Rv 1592–1594）；区块内实际有 4 个插入位点（A 75 条，含 1 条反向的 rid 155；B 2 条；另有 C、D 各 2 条），rid 206 为 IS 嵌套 IS。
- 现象：R10 比 R2 低 500 万（250kbp，几乎是该数据集整体下降的全部来源），列数 R1 3270 / R2 4859 / R10 5324；损失全部在 81 条带插入的序列上，其余 261 条序列略有改善。
- 排除的假设：
  - 不是标记导致锚点消失：这些序列在区块 ±3 kb 内没有任何 q 侧标记区间；包住插入的分段在 R2 和 R10 中形状几乎相同（q 约 2400 bp，t 约 1045 bp，带宽标志 0），只是起点挪了约 200 bp。
  - 不是带宽：用 `-B` 强制自适应带后仍是 53 对 21 的拆分。
  - 不是"X–IS–X"直接重复：插入两侧最长的直接重复只有 12 bp。
- 真实情况：这是**两个相距约 55 bp 的不同 IS6110 插入位点**（用 IS 起始序列 `TGAACCGCCCCGGCAT` 前紧接的序列判定）：
  - A 位点（参考约 1257 之后，`CAGAGATT` 后）：74 条，最先加入的是 rid 160；
  - B 位点（参考约 1313 之后，`CGGCGGTT` 后）：2 条，其中 **rid 125 是所有插入序列中第一个加入的**。

| | 放在 A 位点（列 1259） | 叠在 B 位点的分支上 | 按位置同源放对 |
|---|---|---|---|
| R1 | 1 条 A | 73 条 A + 2 条 B | 3 / 76 |
| R2 | 1 条 A | 73 条 A + 2 条 B | 3 / 76 |
| R10 | 53 条 A | 21 条 A + 2 条 B | 55 / 76 |

- 机制：渐进式 POA 是"先到先得"。rid 125 在 B 位点建了 IS 分支；之后 A 位点的序列如果在两个位点之间约 55 bp 的侧翼上没有锚点，POA 会按得分最优把 IS 叠到已有分支上（只需错开 55 bp 侧翼，比新开 1.36 kb 的插入分支便宜得多）。R10 中 rid 191 以后的 53 条序列，恰好在侧翼上有锚点（例如 rid 191 的 q 2654 对 t 1296，处在插入之后的对角线上），被钉在正确的 A 位点；rid 160 到 190 的 21 条没有，跟着 B 分支走了。A 位点被拆成两组，两组之间每一对都要为整个 IS 扣分，原始 SP 因此下降。
- 为什么正好是这 21 条（已核实）：
  - A 位点序列在插入附近的锚点一般是 t 820 / t 1344（或 843 / 1362），间距约 520 bp，而 t 1344 已在 B 位点（1313）之后，所以这一段同时包含 A、B 两个位点和两者之间的侧翼，IS 放在哪里由 POA 自由决定。
  - 叠到已有的 B 分支只需错开 55 bp 侧翼，而在 A 位点新开插入要承担 1358 bp 的 gap 罚分，因此 POA 选择叠到 B 上（错）。
  - rid 191 的锚点碰巧是 q 2654 对 t 1296（k-mer 覆盖参考 1278 到 1296，落在 1258 到 1313 的侧翼内，处在 −1358 的对角线上），被强制放到 A 位点，图里第一次有了 A 分支。这个可命中的窗口只有约 37 bp。
  - 之后的 A 位点序列即使锚点与 rid 160 相同（如 rid 195 也是 t 820 / 1344），走已有的 A 分支是完美匹配，所以都放对了。
  - 核对结果：错放的 21 条中，20 条正好是 rid 191 之前加入的全部 A 位点序列（rid 160 到 190）；放对的 53 条全部 rid ≥ 191。例外是 rid 240（锚点 t 978 / 1505，放错），推测与静态带范围有关，未核实。
  - 复核（逐条统计全部 76 条带 IS 的序列）：
    - 加入顺序就是输入顺序（未加 `-p` 时 `ord` 由 `std::iota` 生成）。
    - A、B 两份 IS 在 1358 bp 中只差 1 个碱基，所以叠到 B 分支上几乎能拿满匹配分。
    - R10 统计：20 条（无关键锚点、无 A 分支）全部放错；rid 191（有关键锚点、无 A 分支）放对；50 条（无关键锚点、已有 A 分支）放对；2 条（有关键锚点、已有 A 分支）放对；rid 240（无关键锚点、已有 A 分支）放错。
    - rid 240 的例外由带宽造成：用 `-B` 强制自适应带重跑后，它就放在 A 位点（列 1259）。
    - R2 中 rid 206（A 位点，带两份串联的 IS6110，IS 起点在 1258 和 2509）没能带动后面的序列，主要原因是：它加入之前，rid 160 到 205 的 A 单拷贝序列已在图里留下一条完全匹配的错误路径 `L → IS（与 B 的 IS 同列）→ F（单独成列）→ R`。rid 206 的 IS2 和 F 复用了这条路径，多出的 IS1 只能作为新插入塞到前面，与参考的 F 交错；之后的 A 单拷贝序列沿这条零罚分路径走，一直错下去。
    - R2 实际排法（L：参考 ≤1257；F：参考 1258 到 1313；R：参考 ≥1314；按实测列号）：
      ```
      列区间          …1258 │ 1259 ──── 2509 │ 2510 ──── 4195 │ 4196 ─ 4253 │ 4254…
      参考              L   │ F·············· │ ··············· │ ·········   │  R
      B    (rid 125)    L   │ F·············· │ IS············· │ ·········   │  R
      A单  (73 条)      L   │ ················ │ IS············· │ F           │  R
      A双  (rid 206)    L   │ IS1(与F交错)···· │ IS2············ │ F           │  R
      ```
      实测：A 单拷贝的 IS 与 B 的 IS 共用 1321 列；rid 206 的 IS2 与 B 的 IS 共用 1292 列；rid 206 的 IS1 与参考的 F 共用 53 列；参考的 F 有 53 bp 在第 1259 到 2509 列、3 bp 在第 4196 到 4253 列。
    - 期望排法（位置同源）：
      ```
      列区间            L │ A位点IS列 │ A双多出的IS列 │ F列 │ B位点IS列 │ R
      参考              L │ ········· │ ············ │  F  │ ········· │ R
      B    (2 条)       L │ ········· │ ············ │  F  │ IS        │ R
      A单  (73 条)      L │ IS        │ ············ │  F  │ ········· │ R
      A双  (rid 206)    L │ IS        │ IS           │  F  │ ········· │ R
      ```
      rid 206 两份 IS 中哪一份算"多出来的"有歧义，只要所有序列处理一致即可。
    - R10 实际排法（按实测列号）：
      ```
      列区间            L │ C1 1259─2616 │ C2 2617─2674 │ C3 2675─4517 │ C4 4518─4588 │ R
      参考              L │ ············ │ F            │ ············ │ ·            │ R
      B    (2 条)       L │ ············ │ F            │ IS           │ ·            │ R
      A单对 (53 条)     L │ IS           │ F            │ ············ │ ·            │ R
      A单错 (21 条)     L │ ············ │ ·            │ IS           │ F            │ R
      A双  (rid 206)    L │ IS1          │ ·            │ IS2          │ F            │ R
      ```
      实测：放对的 A（rid 191）F 与参考 F 共用 46 列，IS 与 B 的 IS 共用 0 列；放错的 A（rid 160）IS 与 B 的 IS 共用 1321 列，F 与参考 F 只共用 3 列；rid 206 的 IS1 与放对的 A 的 IS 共用 1251 列，IS2 与 B 的 IS 共用 1292 列，F 在 C4。参考和 B 的 F 约有 10 bp 落在 C1 末尾（IS 与 F 交界处的小错位）。
    - rid 206 在 R10 中"混着走"：IS1 走正确的 A 分支，IS2 和 F 走错误分支（中间只需跳过 55 bp 的 F，比新开 1358 bp 插入便宜）。
    - 未核实：R10 中 A 分支出现后，后来的序列为什么大多选正确路径（51 条中 50 条）。错误路径在 L 与 IS 交界处可能有少量错配（rid 160 的 L 末端碱基落在 F 的列上），所以可能是正确路径严格更优，也可能是等分时的选择规则，需要核查。
  - R2 中没有任何 A 位点序列有关键锚点（锚点多为 t 1028 / 1550），始终没有出现可用的单拷贝 A 分支，因此 73 条全部叠到 B 上；R1 在此处没有锚点，结果相同。
  - 改进方向：链化选点时保留紧挨大插入两侧的锚点（rid 160 等序列在 −1358 对角线上其实有这样的候选锚点，只是被 min_w 间距跳过了）。这与串联重复里"紧挨 indel 的锚点有害"正好相反，必须以重复区已被标记为前提。
- 与标记的关系：间接的。别处的标记改变了 `chain_dp`（从末端往前按 min_w 贪心选点）的选点，于是侧翼上有没有锚点变成了"碰运气"。
- 结论：**按位置同源，R10 在此位点比 R1 和 R2 更正确，但不一致**；SP 偏爱"一致地错"（全部叠在一起）。这一类位点（相同移动元件插在相距很近的不同位点）的原始 SP 差值不能作为退步的证据，论文报告 SP 时应说明。
- 核查脚本（服务器 `tmp/scripts/`）：`inspect_block.py`（逐序列 SP、分段、锚点、标记）、`ins_stack.py`（插入落点分组）、`ins_groups.py`（分组结构与锚点）。
